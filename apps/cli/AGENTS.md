# apps/cli

`myapp` from the terminal: a Typer CLI, a Textual TUI, and a stdio MCP proxy, all on one
HTTP client (`src/myapp/client.py`). Read `README.md` first for the command reference;
this file covers only what's specific to the code.

## Hard boundaries

- No business logic or validation here. Every command calls a `myapp.client` function;
  the API owns every rule. A check you're tempted to add to `cli.py` belongs in `apps/api`.
- `src/myapp/mcp_server.py` defines zero tools of its own — it proxies every list/call to
  the API's own MCP server at `<api_url>/mcp` (`apps/api/src/api/mcp.py`). A new tool is
  added there, not here.
- `src/myapp/theme.json` is generated by `pnpm tokens:build`; don't hand-edit it
  (`docs/design-system.md`).

## Commands (from the repo root; package name is `cli`)

```bash
pnpm --filter cli lint        # ruff check + ruff format --check
pnpm --filter cli typecheck   # pyright
pnpm --filter cli test        # pytest, coverage fail_under = 94 (pyproject.toml)
```

None need the local database: tests fake the API (`fake_fetch` in `test_status.py`, a real
in-process `FastMCP` server standing in for the API in `test_mcp.py`) — never Postgres.
There's no `pnpm --filter cli build`; `scripts/build-packages.sh` (`pnpm build:packages`)
`uv build`s the wheel/sdist and packs the `.mcpb` for a release.

## Files to know

- `client.py` — `HealthReport` (the one dataclass every surface shares), `fetch_health`,
  and `DEFAULT_API_URL` (`release_api_url()` or `localhost:8000`).
- `cli.py` — `status`/`tui`/`mcp` commands, each a thin wrapper over `client.py`; bare
  `myapp` opens the TUI only when `interactive_terminal()` is true, else prints `--help`.
- `tui.py` — `MyappApp` (Textual): `design_system_themes()` reads `theme.json` and
  registers `myapp-dark`/`myapp-light` as real Textual themes.
- `mcp_server.py` — `build_server`: a `FastMCP` proxy, `provider_error_strategy="raise"`
  so an unreachable API surfaces as a clear MCP error instead of an empty tool list.
- `mcpb/manifest.json`'s `tools` array is generated, through `pnpm contract:generate`
  (`scripts/generate-mcpb-tools.mjs`), from every tool `apps/api/src/api/mcp.py`
  registers — never hand-edit it; `pnpm contract:check` fails the build when it's stale.

## Conventions and gotchas

- API URL resolution order: `--api-url` flag, then `MYAPP_API_URL`, then a release build's
  own baked-in API, then `http://localhost:8000` (`client.py`'s `DEFAULT_API_URL`).
- `release_api_url.txt` is gitignored and only exists in a release build
  (`scripts/build-packages.sh --api-url`); a checkout falls back to `localhost:8000`.
- Exit codes: `0` healthy/succeeded, `1` not healthy/failed, `2` usage error (Typer).

## Tests

Per the root `CLAUDE.md` "Tests" section, this directory owns argument parsing, output
formatting and exit codes — never the API's own rules, which belong to `apps/api/tests`.
`test_status.py` tests the CLI command via `CliRunner` with a monkeypatched `fetch_health`;
`test_mcp.py` proves `mcp_server.py` forwards a call to a fake upstream and relays an
unreachable API as a clear error, not `api.mcp`'s own tool contract (that's
`apps/api/tests/test_mcp.py`'s job).
